# 文创试销报价和打样记录

价格和交期来自供应商书面报价，打样通过数来自工艺专员，渠道数量和季度上限来自试销采购。 数据全部为合成业务记录。文件使用 UTF-8 JSON，时间均为北京时间，货币如无单独说明均为人民币分。

## 查阅交接数据

使用 Python 3.11 标准库。在仓库根目录运行 `python3 inspect_delivery.py` 查看交接文件和行数，或在后面加文件名（含 `.json`）查看该文件的第一条记录。这个入口仅供查阅交接资料。

## 数据约定

- `samples.json` 工艺试制批及已检件数、合格件数，accepted 为空表示还未获得复验结果。历史记录的 variant 为历史，当前同名款的结果并非独立工艺。
- `variants.json` 初选和可用替代工艺。报价中 process 与 tool 必须匹配，拟售标价为扣渠道费前。
- `quotes.json` 档位每组为起订件数、对应全单每件价，固定费用按一次已合并订单计。不同 quote 不共用阶梯。first_delivery 为完成该工单的到货日。
- `capacity.json` 相同工装的重叠窗口不能让多套工艺重复占用同一时段。units 为窗口内加工总件数，含预计不合格品。
- `channels.json` 各渠道首发日，可售上限和最低可卖件数，毛利率口径用扣渠道费后的实收，计入同批未售成本。不同渠道不能对同一件良品重复销售。
- `demand_cases.json` 采购会提交的渠道需求情景。expected 是预期愿意购买的数量，实际还受渠道上限和可交付良品量限制。情景名称跨渠道表示同一组假设。
- `committed.json` 已签数量和支出，列入总预算且占用对应报价窗口。
- `reviews.json` 立项核算时点、项目的总支出上限和当期风险政策。

## 检查资料

运行 `python3 -m unittest discover -s tests -v`。检查会读取当前交接文件，核对该业务所需的关键原始证据是否齐备。
